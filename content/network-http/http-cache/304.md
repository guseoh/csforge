# 304 Not Modified 응답

`304 Not Modified`는 조건부 GET 또는 HEAD에서 **클라이언트가 이미 저장한 표현을 계속 재사용할 수 있다고 판단될 때** 사용하는 응답이다. 서버는 새 표현 콘텐츠를 다시 보내지 않고, 클라이언트나 캐시가 기존 본문을 사용하게 한다.

```text
저장된 본문 + 검증자
        ↓ 조건부 GET
서버가 검증자 비교
        ↓ 일치
304 Not Modified
        ↓
저장된 본문 재사용
```

### 304는 일반적인 ‘변화 없음’ 상태 코드가 아니다

304는 애플리케이션의 업무 상태가 바뀌지 않았다는 뜻이 아니다. `If-None-Match`나 `If-Modified-Since` 같은 HTTP 전제조건을 평가한 결과, 요청한 표현을 새로 전송할 필요가 없다고 판단한 **조건부 요청 전용 응답**이다.

### 본문은 없지만 캐시 메타데이터는 갱신할 수 있다

304 응답에는 새 표현 콘텐츠가 없지만 캐시 상태를 갱신하는 데 필요한 `Date`, `ETag`, `Cache-Control`, `Expires`, `Vary` 같은 메타데이터가 포함될 수 있다. 수신자는 기존 저장 본문을 유지하면서 304의 메타데이터를 반영해 캐시 항목을 갱신한다.

```text
기존 저장 항목
[본문 A + 오래된 메타데이터]
           +
304의 새 메타데이터
           ↓
[본문 A + 갱신된 메타데이터]
```

### 저장된 본문이 없으면 304만으로 복구할 수 없다

검증자만 남겨 두고 실제 저장 본문을 삭제한 클라이언트가 304를 받으면 최종 표현을 만들 수 없다. 검증자는 표현 자체가 아니라 **비교를 위한 증표**이기 때문이다.

따라서 저장된 표현이 없다면 조건부 요청을 보내지 않거나, 잘못 304를 받은 경우 전체 GET으로 다시 복구하는 경로가 필요하다.

핵심은 **304가 새 본문을 전달하는 응답이 아니라 이미 저장된 표현을 재사용하라는 조건부 요청의 검증 결과라는 점**이다.
