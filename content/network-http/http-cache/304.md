# 304 Not Modified 응답

저장된 표현을 가진 클라이언트가 조건부 GET 또는 HEAD를 보내면 서버는 해당 표현을 다시 전송할 필요가 없는 경우 304를 반환합니다. 이 응답에는 새 표현 콘텐츠가 없습니다.

```csforge-viz
{
  "version": 1,
  "type": "network-area",
  "title": "304 Not Modified 응답",
  "description": "프로토콜 상태·요청 경계와 이전·이후 결과를 고정 예제로 확인합니다.",
  "example": "304"
}
```

그림에서는 기존 본문 A와 검증자 "v7"을 보존하고, 조건부 요청에 대한 304에서 갱신된 캐시 제어 정보를 받는 상황을 보여 줍니다. 캐시는 일치하는 저장 응답을 찾아 304가 제공한 필드를 반영하고 신선도와 재사용 자격을 다시 평가합니다. 모든 저장 항목을 무조건 같은 메타데이터로 바꾸는 것이 아닙니다.

### 저장 본문이 없다면 다시 받아야 합니다

ETag만 남아 있고 본문이 제거된 상태라면 304에서 새로운 콘텐츠를 얻을 수 없습니다. 그러므로 저장 표현이 없는 경우에는 적절한 일반 GET으로 본문을 다시 확보하는 복구 경로가 필요합니다.

304는 데이터베이스 상태나 애플리케이션의 업무 처리 여부가 변하지 않았다는 의미가 아닙니다. 요청에 선택된 표현과 HTTP 전제조건에 관한 응답입니다. 클라이언트가 인증·인가를 통과했는지와 캐시 재사용 자격도 별도입니다.

관련 명세는 RFC 9110 §15.4.5와 RFC 9111 §4.3.4입니다.
