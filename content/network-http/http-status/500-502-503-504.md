# 500·502·503·504의 실패 경계

5xx는 server error class지만 `어느 HTTP participant가 어떤 이유로 실패했는가`는 status마다 다르다.

`500 Internal Server Error`는 server가 request를 처리하는 중 예상하지 못한 condition을 만나 요청을 완료할 수 없을 때 사용하는 일반적인 내부 오류다.

`502 Bad Gateway`는 gateway나 proxy가 upstream server와 통신하면서 **유효하지 않은 response를 받은 경우**다. 이때 502를 client에게 반환하는 주체는 중간 gateway이며, client가 직접 origin의 500을 받은 상황과 다르다.

`503 Service Unavailable`은 server가 temporary overload나 maintenance처럼 현재 요청을 처리할 준비가 되지 않은 상태다. 가능하면 `Retry-After`를 사용해 예상되는 복구 시점을 알려 줄 수 있다.

`504 Gateway Timeout`은 gateway나 proxy가 request를 처리하기 위해 필요한 upstream server의 response를 제시간에 받지 못한 경우다.

```text
500 → 현재 server의 내부 처리 실패
502 → gateway가 upstream에서 invalid response를 받음
503 → server가 일시적으로 요청 처리 불가
504 → gateway가 upstream response를 제때 받지 못함
```

이 status들은 retry 가능성을 자동으로 보장하지 않는다. 특히 gateway timeout이 발생했더라도 upstream이 request를 일부 또는 전부 처리했을 가능성은 남을 수 있다. 따라서 status의 의미와 request method의 retry/idempotency semantics를 함께 봐야 한다.

핵심은 5xx를 하나의 `서버 오류`로 뭉개지 않고 **오류를 반환한 HTTP hop과 실패 종류를 구분하는 것**이다.
