# 200, 201, 202 and 204

200은 request가 성공해 representation이나 결과를 반환하는 일반 성공이고, 201은 resource가 생성되어 Location 등으로 식별될 수 있음을 나타낸다. 202는 처리를 수락했지만 완료를 보장하지 않는 비동기 결과다.

204는 성공했지만 response content가 없는 상태다. body가 필요한 client에게 204를 주거나 아직 처리되지 않은 command에 200을 주면 client의 retry와 polling semantics가 흐려진다.

### Backend 연결

import Apply가 DB commit 뒤 indexing을 비동기로 수행하면 canonical 저장 완료와 search projection 완료를 구분해 202 또는 200 contract를 정한다. status와 job status endpoint를 함께 설계한다.
