# 200·201·202·204의 차이

2xx는 모두 successful response class에 속하지만, 요청이 어떤 상태까지 진행되었는지와 response content의 의미는 서로 다르다.

`200 OK`는 요청이 성공했다는 가장 일반적인 response다. method에 따라 selected representation이나 처리 결과를 content로 반환할 수 있다.

`201 Created`는 요청이 처리된 결과 하나 이상의 resource가 생성되었음을 나타낸다. 새 resource를 식별할 URI는 `Location` field나 request target의 의미를 통해 알 수 있다.

`202 Accepted`는 요청을 **처리 대상으로 받아들였지만 처리가 아직 완료되지 않았을 수 있음**을 뜻한다. HTTP 자체는 이후 비동기 작업이 반드시 성공한다고 보장하지 않는다. 그래서 장기 작업이라면 application이 별도의 progress나 result resource를 제공할 수 있다.

`204 No Content`는 요청은 성공했지만 response content를 보내지 않는 경우다. client가 새 representation을 받을 필요가 없을 때 사용할 수 있다.

```text
200 → 성공, 일반적인 결과 반환 가능
201 → 성공 + resource 생성
202 → 처리를 수락했지만 완료는 아님
204 → 성공 + response content 없음
```

이 차이를 이해하면 모든 성공을 `200` 하나로 표현하는 대신, **client가 현재 operation의 상태를 어떻게 해석해야 하는지** HTTP response 자체로 더 정확하게 전달할 수 있다.
