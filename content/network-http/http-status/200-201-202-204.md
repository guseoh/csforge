# 성공 응답: 200·201·202·204

같은 성공 응답이라도 조회 결과를 얻은 상황, 새 리소스를 생성한 상황, 비동기 작업을 접수한 상황은 다릅니다. HTTP의 2xx 상태 코드는 클라이언트가 요청 처리의 현재 상태와 반환 콘텐츠를 해석하도록 돕습니다.

| 상태 | 의미 | API 예시 |
| --- | --- | --- |
| 200 OK | 메서드에 맞는 일반적인 성공 | GET /orders/42의 주문 표현 반환 |
| 201 Created | 요청으로 하나 이상의 리소스 생성 | POST /orders로 주문 생성 |
| 202 Accepted | 요청 접수, 처리 미완료 | 대량 보고서 생성 작업 접수 |
| 204 No Content | 성공했지만 응답 콘텐츠 없음 | 변경 완료 후 새 표현이 필요 없는 PUT |

### 생성 완료와 처리 접수의 차이

201은 요청으로 리소스가 생성된 결과입니다. 생성한 주 리소스는 Location으로 식별하거나, 해당 필드가 없다면 요청 대상 URI로 식별합니다. 202는 처리를 받아들였지만 아직 완료되지 않았다는 응답입니다. 예를 들어 비동기 보고서 생성에서는 202와 작업 ID, 상태 조회 URI를 제공하는 계약을 설계할 수 있습니다. 202만으로 최종 보고서가 성공적으로 생성됐다고 판단해서는 안 됩니다.

### 204와 빈 200

204 응답에는 콘텐츠가 없습니다. 200 응답의 콘텐츠 의미는 요청 메서드와 API 계약에 따라 달라집니다. 예를 들어 결과 목록이 비어 있다면 200과 빈 배열을 반환할 수 있습니다. 이는 응답 콘텐츠 자체를 보내지 않는 204와 다른 계약입니다.

HTTP 성공 상태는 프로토콜의 응답 의미입니다. 서비스의 최종 업무 상태나 데이터 내구성은 실제 애플리케이션의 처리·트랜잭션 계약으로 확인해야 합니다.
