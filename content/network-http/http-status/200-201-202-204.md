# 200, 201, 202·204

`200 OK`는 요청을 성공적으로 처리해 representation이나 결과를 반환하는 일반적인 성공이고, `201 Created`는 요청의 결과로 resource가 생성됐음을 표현하며 `Location`이나 representation으로 새 identity를 알려줄 수 있다. `202 Accepted`는 요청이 처리 대상으로 접수됐지만 실제 처리가 완료됐다는 보장은 하지 않는다. 따라서 200/201의 동기 처리와 202의 operation status를 혼동하지 않는다.

`204 No Content`는 성공했지만 응답 content를 보내지 않는 상태다. body가 필요한 client에 204를 주거나 아직 처리되지 않은 command에 200을 주면 client가 결과를 해석하거나 polling·retry할 방법이 흐려진다. status code는 business object의 모든 field나 downstream 작업 완료를 자동으로 전달하지 않으므로 headers와 응답 contract를 함께 설계한다.

어떤 backend가 PostgreSQL canonical write 뒤 별도 검색 projection 색인을 비동기로 수행한다면 canonical 저장 완료와 projection 완료를 분리한다. 동기 canonical 결과는 200/201, 비동기 workflow 접수는 202와 작업 상태 endpoint로 표현하고, 어느 상태를 사용자 성공으로 보일지 명시한다. CSForge V1처럼 PostgreSQL을 직접 검색하는 구조에는 존재하지 않는 색인 완료 단계를 현재 구현처럼 덧붙이지 않는다.
