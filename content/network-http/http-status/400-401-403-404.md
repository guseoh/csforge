# 400, 401, 403 and 404

`400 Bad Request`는 malformed syntax, invalid message framing, deceptive routing처럼 server가 client error로 인식한 이유 때문에 request를 처리할 수 없거나 처리하지 않겠다는 상태다. `401 Unauthorized`는 target resource에 유효한 authentication credential이 없어 request가 적용되지 않은 상태이며, **401 response를 생성하는 server는 `WWW-Authenticate`에 최소 하나의 applicable challenge를 보내야 한다.** `403 Forbidden`은 server가 request를 이해했지만 수행을 거부하는 상태이고, `404 Not Found`는 target resource를 찾지 못했거나 존재 여부 공개를 원하지 않는 상태일 수 있다.

401과 403을 단순히 “로그인 전/로그인 후”로만 외우지 않는다. authentication scheme과 credential 상태에 따라 401 challenge가 사용되고, credential을 제공해도 insufficient permission이나 정책상 거부되는 경우 403이 될 수 있다. server는 forbidden resource의 존재를 숨기기 위해 404를 사용할 수도 있으므로 외부 response와 내부 audit reason을 분리한다.

CSForge API는 malformed request, authentication challenge, authorization refusal과 missing concept를 안정된 error contract로 매핑한다. client가 400/401/403/404를 모두 같은 retry 대상으로 취급하지 않도록 recovery action과 안전한 error code를 구분하고, 내부 stack trace·resource existence 같은 민감 정보는 threat model에 맞춰 제한한다.
