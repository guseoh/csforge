# 요청 오류: 400·401·403·404

4xx 상태 코드는 모두 클라이언트 오류 계열에 속하지만 요청을 수행할 수 없는 이유는 서로 다르다. 단순히 `클라이언트 잘못`이라고 묶기보다 **어떤 조건을 바꾸면 다음 요청이 성공할 수 있는지**를 기준으로 구분하면 이해하기 쉽다.

`400 Bad Request`는 잘못된 문법이나 유효하지 않은 메시지 프레이밍처럼, 서버가 클라이언트 쪽 오류로 판단한 이유로 요청을 처리할 수 없거나 처리하지 않겠다는 일반적인 상태다.

`401 Unauthorized`는 이름과 달리 주로 **유효한 인증 정보가 없거나 인증이 필요한 상태**를 나타낸다. 401 응답에는 대상 리소스에 적용할 수 있는 인증 challenge를 `WWW-Authenticate` 필드로 제공해야 한다.

`403 Forbidden`은 서버가 요청을 이해했지만 수행을 거부하는 상태다. 인증된 사용자라도 필요한 권한이 없거나 정책상 요청이 허용되지 않는 경우가 포함될 수 있다. 새로운 인증 정보를 보내도 반드시 해결되는 상태는 아니다.

`404 Not Found`는 대상 리소스의 현재 표현을 찾지 못했거나, 서버가 리소스의 존재 여부를 공개하지 않으려는 경우에도 사용할 수 있다.

```text
400 → 요청 자체를 처리하기 어려운 문제
401 → 인증 challenge가 필요함
403 → 요청은 이해했지만 수행을 거부함
404 → 대상을 찾지 못했거나 존재 여부를 공개하지 않음
```

인증 여부만 보고 `401 = 로그인 안 함`, `403 = 로그인했지만 권한 없음`으로 고정하면 예외를 놓칠 수 있다. 핵심은 **인증 정보를 새로 제시해야 하는가, 서버가 현재 요청을 허용하지 않는가, 대상 자체를 찾을 수 없는가**라는 HTTP 의미를 구분하는 것이다.
