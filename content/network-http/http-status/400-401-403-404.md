# 400, 401, 403 and 404

400은 malformed syntax나 invalid request shape를, 401은 authentication challenge가 필요한 상태를, 403은 server가 이해했지만 허용하지 않는 상태를, 404는 target resource를 찾지 못한 상태를 표현한다. authentication과 authorization을 같은 오류로 숨길지는 threat model에 따라 결정한다.

404는 resource가 실제로 없거나 존재를 공개하지 않으려는 정책일 수 있어 domain semantics와 구분한다. validation detail을 body에 제공하더라도 status class가 client retry 가능성을 잘못 암시하지 않게 한다.

### Backend 연결

Bean Validation 실패와 permission failure, missing concept를 각각 안정된 error contract로 매핑한다. 401을 받은 client의 재인증과 403의 권한 수정, 404의 사용자 안내를 다르게 처리한다.
