# 400, 401, 403 and 404

`400 Bad Request`는 malformed syntax나 처리할 수 없는 request shape를, `401 Unauthorized`는 유효한 authentication credential이 없거나 challenge가 필요한 상태를, `403 Forbidden`은 server가 request를 이해했지만 허용하지 않는 상태를, `404 Not Found`는 현재 URI에서 target resource를 찾지 못한 상태를 표현한다. 401 응답은 일반적으로 `WWW-Authenticate` challenge와 연결되며, authentication과 authorization을 같은 외부 오류로 숨길지는 threat model에 따라 결정한다.

404는 resource가 실제로 없을 수도 있고 존재 여부 공개를 피하는 정책으로 permission failure를 숨긴 결과일 수도 있다. 400은 syntax/shape 문제, 401은 credential, 403은 permission이라는 기본 경계를 유지하되 실제 API contract가 resource enumeration을 어떻게 다룰지 명시한다. validation detail을 body에 제공해도 client가 영구 오류를 무한 retry하지 않도록 retryability를 별도로 표현한다.

CSForge API는 Bean Validation 실패, authentication/permission failure와 missing concept를 안정된 error contract로 매핑한다. 401을 받은 client의 재인증, 403의 권한 수정, 404의 사용자 안내를 다르게 처리하고, 내부 audit detail과 외부 response detail을 분리한다.
