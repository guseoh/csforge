# 409 Conflict와 412 Precondition Failed

`409 Conflict`는 request가 현재 target resource의 상태와 충돌해 요청을 완료할 수 없는 경우를 나타낸다. 일반적으로 client가 conflict의 원인을 이해하고 request를 수정한 뒤 다시 제출할 수 있는 상황에 사용된다.

예를 들어 client가 수정하려는 resource의 현재 상태가 이미 다른 변경과 충돌했거나, 요청한 상태 전환이 현재 resource state에서 성립하지 않는다면 409가 후보가 될 수 있다. 구체적인 conflict 의미는 resource와 application semantics가 설명한다.

`412 Precondition Failed`는 더 구체적이다. client가 `If-Match`, `If-Unmodified-Since` 같은 HTTP conditional field로 **이 조건이 참일 때만 request를 적용해 달라**고 했는데 server가 현재 상태를 평가한 결과 그 조건이 거짓인 경우다.

```text
409 Conflict
  → 현재 resource state와 request가 충돌

412 Precondition Failed
  → request가 명시한 HTTP precondition이 false
```

예를 들어 ETag가 `v3`일 때만 수정하겠다는 `If-Match` request가 있는데 resource가 이미 `v4`라면 412로 conditional update를 중단할 수 있다. 이 경우 request 자체의 business 의미보다 **client가 걸어 둔 HTTP precondition이 만족되지 않았다는 것**이 핵심이다.

둘 다 현재 상태 때문에 write가 거부될 수 있지만, 409는 일반적인 resource-state conflict이고 412는 HTTP conditional request 평가 결과라는 차이를 유지해야 한다.
