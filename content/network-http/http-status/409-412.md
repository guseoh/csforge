# 상태 충돌과 조건부 요청: 409·412

`409 Conflict`는 요청이 현재 대상 리소스의 상태와 충돌해 완료될 수 없는 경우를 나타낸다. 보통 클라이언트가 충돌 원인을 이해하고 요청을 수정해 다시 제출할 수 있는 상황에 사용한다.

예를 들어 수정하려는 리소스의 현재 상태가 다른 변경과 충돌하거나, 요청한 상태 전환이 현재 상태에서 성립하지 않는다면 409를 고려할 수 있다. 구체적인 충돌 의미는 리소스와 애플리케이션 계약이 설명한다.

`412 Precondition Failed`는 더 구체적이다. 클라이언트가 `If-Match`, `If-Unmodified-Since` 같은 HTTP 조건부 필드로 **조건이 참일 때만 요청을 적용해 달라**고 했는데, 서버가 현재 상태를 평가한 결과 조건이 거짓일 때 사용한다.

```text
409 Conflict
  → 현재 리소스 상태와 요청이 충돌함

412 Precondition Failed
  → 요청에 명시한 HTTP 전제조건이 거짓임
```

예를 들어 ETag가 `v3`일 때만 수정하겠다는 `If-Match` 요청을 받았는데 리소스가 이미 `v4`라면 412로 조건부 수정을 중단할 수 있다. 이때 핵심은 요청 자체의 업무 의미보다 **클라이언트가 설정한 HTTP 전제조건이 만족되지 않았다는 점**이다.

두 상태 모두 현재 상태 때문에 변경이 거부될 수 있지만, 409는 일반적인 리소스 상태 충돌이고 412는 HTTP 조건부 요청을 평가한 결과라는 차이가 있다.
