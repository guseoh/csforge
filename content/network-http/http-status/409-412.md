# 409 and 412

`409 Conflict`는 request가 현재 resource state와 충돌해 처리할 수 없음을 나타내고, `412 Precondition Failed`는 request가 포함한 `If-Match`나 `If-Unmodified-Since` 같은 precondition이 현재 representation state에서 거짓임을 나타낸다. 둘 다 concurrent update에서 보일 수 있지만, 412는 명시적인 conditional header 평가 실패라는 점에서 일반적인 domain conflict와 다르다.

client는 412를 받으면 최신 representation/ETag를 다시 읽고 merge하거나 사용자의 선택으로 version을 갱신해야 하며, 409는 conflict reason에 맞는 domain recovery가 필요하다. 무조건 같은 request를 retry하면 충돌을 반복할 수 있으므로 현재 version이나 conflict detail을 안전하게 제공하고, client가 stale write를 조용히 덮어쓰지 않게 한다.

CSForge content reimport에서 명시한 version precondition이 현재 canonical version과 다르면 412, 동일 stable key에 incompatible payload가 들어오면 409처럼 계약을 나눌 수 있다. error response에는 recovery에 필요한 최소 metadata만 제공하고 canonical data를 과도하게 노출하지 않는다.
