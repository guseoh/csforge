# 상태 충돌과 조건부 요청: 409·412

409 Conflict는 현재 대상 리소스 상태와 요청이 충돌하여 완료할 수 없는 경우입니다. 예를 들어 취소된 주문을 출고하려는 요청은 업무 상태 충돌로 처리할 수 있습니다.

412 Precondition Failed는 요청에 명시한 HTTP 전제조건의 평가 결과가 거짓일 때 사용하는 상태입니다.

### 동시 수정의 예

A와 B가 ETag "v7"인 문서를 읽은 뒤 A가 수정하여 "v8"이 되었다고 가정합니다. B가 오래된 표현을 저장할 때 다음 조건을 사용할 수 있습니다.

```http
PUT /documents/42 HTTP/1.1
If-Match: "v7"
```

강한 ETag 비교에서 조건이 실패하면 일반적으로 변경하지 않고 412를 반환합니다. 조건 검사와 변경은 원자적으로 보호하여 검사 직후 다른 변경이 끼어들지 않도록 해야 합니다.

B는 최신 표현을 다시 읽고 차이를 검토한 뒤 병합하거나 수정을 중단할 수 있습니다. 412만으로 이전에 응답을 받지 못한 요청의 성공 여부까지 증명할 수는 없습니다. 409와 412는 모두 충돌 상황에서 등장할 수 있지만 명시적 HTTP 전제조건의 실패에는 412를 사용합니다.
