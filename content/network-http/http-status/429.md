# 429

429 Too Many Requests는 client가 일정 시간 동안 허용된 요청 rate나 quota를 초과했음을 나타낸다. Retry-After가 있으면 client는 제시된 delay나 날짜를 고려해야 하며, 없더라도 무제한 즉시 retry를 하지 않는다.

rate limit은 identity, IP, token, route, global capacity 중 어떤 기준인지 명시한다. 429를 보내도 이미 queue에 들어간 요청과 다른 client의 quota가 자동으로 취소되는 것은 아니다.

### Backend 연결

quiz submit과 search API의 per-user·global limit을 구분하고 response에 stable error code를 둔다. retry backoff와 server queue admission을 함께 설계한다.
