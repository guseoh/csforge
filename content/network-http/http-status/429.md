# 429

`429 Too Many Requests`는 **server가 사용하는 counting 정책에서 user가 일정 시간 동안 너무 많은 request를 보냈다고 판단한 rate-limiting 상태**다. RFC 6585는 user를 어떤 identity로 식별하는지, request를 per-resource·server-wide·여러 server에 걸쳐 어떻게 세는지는 정의하지 않는다. 따라서 IP·credential·cookie·route 등 실제 limiter key와 window는 application/server policy로 명시해야 한다.

429 response representation은 가능하면 제한 조건을 설명하고 `Retry-After`를 포함해 다시 시도하기까지의 시간을 알려 줄 수 있다. `Retry-After`는 optional이므로 없다고 즉시 retry해도 된다는 뜻은 아니며, client는 bounded backoff와 jitter를 사용한다. 반대로 service 전체가 temporary overload나 maintenance 때문에 request를 처리할 수 없는 상황은 503 semantics와 구분한다.

429를 반환했다고 이미 처리 중이거나 queue에 들어간 request가 자동 취소되는 것은 아니다. side effect가 시작됐는지와 retry가 안전한지는 method/idempotency contract를 별도로 확인해야 한다. CSForge quiz submit과 search API에서는 per-user·route limit과 service overload를 분리하고, stable error code와 필요 시 `Retry-After`를 제공해 retry storm을 피한다.
