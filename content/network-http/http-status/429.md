# 429

`429 Too Many Requests`는 server가 특정 client, identity, route 또는 공유 capacity에 대한 요청 rate/quota를 초과했다고 판단했음을 나타낸다. `Retry-After`가 있으면 client는 seconds delay 또는 HTTP-date를 기준으로 기다려야 하며, 없더라도 무제한 즉시 retry하지 않고 backoff와 jitter를 사용한다. 429 자체가 모든 rate limiter 구현이 동일하다는 뜻은 아니다.

rate limit의 key가 identity·IP·token·route·global capacity 중 무엇인지와 window, burst, queue 처리 정책을 명시한다. 429를 반환해도 이미 처리 중이거나 queue에 들어간 요청이 자동 취소되는 것은 아니며, side effect가 시작됐는지와 retry가 안전한지는 별도다. 서로 다른 client의 quota와 service overload를 같은 숫자로 숨기지 않는다.

CSForge quiz submit과 search API에서 per-user·global limit을 구분하고 stable error code와 필요한 `Retry-After`를 제공한다. client retry backoff, server queue admission·cancellation과 quota 관측을 함께 설계해 429가 retry storm으로 증폭되지 않게 한다.
