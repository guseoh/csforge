# 429 Too Many Requests

`429 Too Many Requests`는 server가 사용하는 rate-limiting 정책에서 한 user가 일정 시간 동안 너무 많은 request를 보냈다고 판단했을 때 사용하는 status다. HTTP 표준은 `user`를 IP, credential, cookie 중 무엇으로 식별해야 하는지나 요청을 어떤 window로 세야 하는지까지 정하지 않는다. 그 부분은 server policy가 정의한다.

따라서 429를 받았다고 `한 IP에서 초당 N회 제한`처럼 특정 algorithm을 추측하면 안 된다. per-user, per-resource, server-wide 또는 여러 server를 합친 limiter 등 다양한 정책이 같은 status를 사용할 수 있다.

### Retry-After는 다시 시도할 시점을 알려 줄 수 있다

429 response에는 `Retry-After` field를 포함해 client가 어느 시점 이후 다시 시도할 수 있는지 알려 줄 수 있다. 하지만 이 field는 optional이므로 없다는 이유만으로 즉시 반복 요청을 보내도 된다는 뜻은 아니다.

```text
request burst
    ↓
rate-limiting policy exceeded
    ↓
429 Too Many Requests
    └─ optional Retry-After
```

429와 `503 Service Unavailable`도 구분해야 한다. 429는 특정 user의 request rate가 policy를 넘었다는 의미이고, 503은 service가 현재 요청을 처리할 수 없는 일시적인 상태를 나타낸다.

또한 RFC 6585는 429 response를 cache에 저장하지 않도록 규정한다. 핵심은 **429가 transport 오류가 아니라 server의 request-rate policy가 현재 요청을 받아들이지 않는다는 HTTP-level feedback**이라는 점이다.
