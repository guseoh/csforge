# 요청 제한과 429

429 Too Many Requests는 서버의 요청률 제한 정책을 초과한 요청에 대한 상태입니다. HTTP는 제한 대상을 사용자, IP, 인증 주체 중 무엇으로 정할지 또는 특정 제한 알고리즘을 강제하지 않습니다.

```csforge-viz
  "example": "429"
}
```

서버는 Retry-After로 재시도까지 기다릴 시간 또는 날짜를 제공할 수 있습니다. 이 필드가 없어도 즉시 무한 재시도하는 것이 적절하지는 않습니다. 다수 클라이언트의 동시 재시도는 제한과 과부하를 악화시킬 수 있습니다. 지수 백오프, 지터, 전체 시간 예산과 최대 시도 횟수를 함께 고려합니다.

### 503과의 구분

429는 요청률 제한에 관한 상태이고 503은 서비스가 일시적으로 요청을 처리할 수 없는 상태입니다. 실제 제한 정책은 사용자별·리소스별·전체 서비스 단위 등으로 구성할 수 있습니다.

RFC 6585는 429 응답을 캐시에 저장하지 않도록 규정합니다. 재시도를 허용하더라도 비멱등 요청의 업무 효과 중복 제어는 별도로 필요합니다.
